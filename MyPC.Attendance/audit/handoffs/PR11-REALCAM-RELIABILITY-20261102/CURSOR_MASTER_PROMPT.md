## Priority P0-A: RTSP/HEVC stability - diagnose before tuning
1. Inventory every source reader and all open/close/stop paths: `backend/app/vision/camera/{gateway,registry,rtsp_probe,native_frame}.py`, camera APIs, enrollment/quality services, and any OpenCV/FFmpeg/go2rtc processes. Determine whether duplicate camera records for the same physical host/path launch redundant RTSP connections; do not assume they do.
2. Document actual transport (`TCP interleaved` versus `UDP`), decoder backend, video codec/profile, negotiated dimensions, GOP/keyframe interval, camera timestamp behavior, open/read/close timeouts, thread count and number of simultaneous consumers. Keep TCP as first controlled test, not an untested universal solution. Compare sequentially with H.264 and a supported substream/main stream where the device/firmware permits. EZVIZ H8 Pro 3K official specs list H.265 and H.264, dual-stream, 2880x1620 max, and wired Ethernet; verify this actual device configuration before changes.
3. Distinguish reference-frame errors limited to joining a stream mid-GOP from recurring corrupt frames after steady state. Instrument error counts by session and timestamp, age of newest good frame, dropped/invalid frames, read/decode/encode latencies, consecutive failure duration, reconnect attempts, actual connection count, network/CPU/RAM load and reconnect cause; report only reliable metrics. Do not infer packet loss from POC errors alone.
4. Design one owned capture/decode pipeline per unique physical stream, with explicit reference counting/leases, bounded queues (latest frame for UI), cancellation, finite timeouts and predictable shutdown. Restart only after bounded exponential backoff with jitter; classify invalid credentials (401 after challenge), invalid RTSP endpoint (404), transport timeouts, codec errors and health degradation separately. Never loop reconnects indefinitely at high rate or keep archiving/removed cameras connected.
5. Protect recognition fidelity: preserve original full-resolution source when required, immutable native frame metadata, real timestamps, source ID, provenance, and freshness. A broken or stale frame must not silently count as healthy LIVE or enter face enrollment / attendance decision. Do not invent clean frames or synthesize employee matches.
6. Add a tested recovery path when HEVC reference frames are lost (wait for a valid independently decodable keyframe, restart session where safe, mark degraded). Do not claim that merely suppressing FFmpeg stderr fixes corruption. Do not globally force `-fflags nobuffer`, `skip_frame`, very small buffers, hardware acceleration, H.264 or a lower resolution without A/B evidence and compatible decoder behavior.
7. Test wired-versus-Wi-Fi and H.265-versus-H.264 only one variable at a time, sequentially, on the same camera. If an external VLC/FFmpeg sequential test also corrupts, classify as device/transport/firmware signal, not proof of application code failure. If external playback stays clean but MyPC corrupts, isolate application reader, concurreny, buffer and transform issues.
